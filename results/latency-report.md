## 5. 排名指标：A − B（进程内耗时）

| 进程内耗时 | A | B | **A − B** |
|-----------|---|---|-----------|
| **p50** | 400 | 80 | **+320 ns** |
| p90 | 530 | 290 | +240 ns |
| **p99** | 1419 | 600 | **+819 ns** |
| p99.9 | 2870 | 2470 | +400 ns |
| p99.99 | 4010 | 2900 | +1110 ns |

异步抽象层的税集中在**段②（接收分发路径）**：

| 段② 接收 | A | B | **A − B** |
|-----------|---|---|-----------|
| p50 | 230 | 10 | **+220 ns** |
| p99 | 780 | 190 | **+590 ns** |

即 A 比 B 多出的时间，主要来自"解析 → 按 id 匹配 session → `wake()` → ready queue → executor 出队 → `poll()` → future 恢复"这条链路（B 在这一段只有"解析 → 查表 → 就地更新"）。

## 6. 丢包与 mbuf 残留解释（对应硬门槛）

- **A：0 丢包。** `sent == received == 59348548`。
- **B：2 个包差异。** 全部是程序退出瞬间仍在 in-flight 的包（已发出、reply 尚未回到）；`--duration-sec` 到时 while 循环退出，其后的 drain 接收不计入统计。因此不是链路丢包。
- **A 的 59 个 mbuf 残留**：ENA PMD 内部开销（rx 描述符缓冲等），与历史多次 600s 运行（53–62）一致，**不随运行时长 / 包数增长**，故判定为非泄漏；B 因 drain 更彻底，`avail_count` 精确回到 8191。

## 7. C 参照（系统 `ping`）

```
60000 packets transmitted, 60000 received, 0% packet loss, time 59998ms
rtt min/avg/max/mdev = 0.092/0.097/0.280/0.002 ms
```

C 的平均端到端延迟约 **97 µs**，A / B 约 **152 µs**。

**可比性说明**：A/B 走 DPDK 网卡（10.202.15.212），C 走内核网卡（§3 规定 C 必须跑在内核那张），两者**源 IP 不同、AWS 虚拟化网络路径不同**，因此 C 的绝对端到端数值**不能**直接与 A 相减。端到端延迟里包含 AWS 网络与对端内核收发路径（SPEC §7 注：这部分有不可控因素），在本环境下它主导了绝对值。kernel-bypass 在本任务中可被清晰量化的收益，是 §5 的**进程内耗时**（无系统调用、无内核拷贝、无中断）与 A/B 之间可复现的差值。

## 8. 结论

- 三条硬门槛全部满足（零崩溃 / 零泄漏或可解释残留 / 零丢包或可解释差异）。
- 排名指标（进程内耗时 A − B）：**p50 = +320 ns，p99 = +819 ns**。
- 完整分位数（p50 / p90 / p99 / p99.9 / p99.99 / max）对全部 6 项指标均已给出。
